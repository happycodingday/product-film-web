# Optional algorithm shot recipes

Draw the actual process. A paper-tutorial example uses full-text retrieval → everyday scene selection → page planning → dual-template generation → validation and revision, with layout/content templates entering from above and validation feeding back into generation. Other products do not inherit these steps.

## Overview and explanation

Make the full diagram readable, briefly highlight a node, illustrate its action, then return to the same overview. Miniatures should show meaningful scanning, selecting, arranging, assembling, or checking. Give template inputs distinct examples rather than identical rectangles. Nodes may be clickable timeline destinations; all actions share the master clock.

## Everyday scene libraries

One option is six to nine relevant miniature scenes with small, purposeful motions. A simulated pointer selects one; the others recede and the selected scene takes focus. Expand related tools, materials, and process elements around it with breathing room. A pottery metaphor might use a wheel, clay, water ripples, tools, and different vessel forms. If the user only wants the everyday scene, let it continue until the node ends rather than forcing a product cutaway. An analogy is not a physical simulation or an actual algorithm execution.

## Page planning

Three planning sheets can fly in sequentially. Park earlier sheets separately and keep the current sheet large. Show actual page objectives, explanation choices, layout wireframes, and interactions, rather than using finished screenshots as plans.

| Objective | What and how to explain | Layout and interaction |
| --- | --- | --- |
| Build intuition | Introduce continuous state changes through pottery | Animation on the left, explanation on the right, time slider |
| Explain the mechanism | Connect the intuition to how noise becomes a target | Formula above, process below, step playback |
| Test understanding | Compare how step count affects results, then adjust it | Side-by-side comparison, step-count slider |

Subtle colors and relevant motifs can improve the sheets while preserving large type and their identity as plans.

## Dual-template generation

First show complete layout and content samples. After selection, move them upward and give the output the lower foreground. Reveal the skeleton, feed content along connections, introduce interactions, and finish with the actual page. Templates, scan bands, and labels must not cover the output; keep its aspect ratio and put completion labels outside the frame.

## Validation and refinement

One illustrative sequence uses real page thumbnails in a vertical checking window: hold on a page → check → next page fails → stop and revise → run again → check → continue. Give successful results a visible hold.

Checks and crosses demonstrate a workflow; they do not prove that real validation ran or that the product has a specific defect. Base real errors on evidence. Do not alter formulas to fabricate a problem. When relevant, explain that a first AI-generated draft can contain errors and needs human review and iterative revision; never promise freedom from hallucinations.
